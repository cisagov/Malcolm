# AWS VPC Flow Logs from cloud exports

Malcolm can ingest AWS VPC Flow Logs downloaded from Amazon S3 or exported
from CloudWatch Logs to S3. This example covers the standard **14-field
VPC Flow Log version 2** format and extended logs with a known field order.
It does not configure AWS polling or grant access to an AWS account.

Use the [streaming AWS VPC Flow Log converter](../shared/bin/aws_vpc_flow_to_json.py)
to turn these text or gzip exports into newline-delimited JSON, then send
the records through Malcolm's existing TLS-protected Filebeat TCP receiver.
Logstash maps their common fields to ECS, while keeping the AWS-specific
fields under `miscbeat` for searches.

## 1. Obtain an export

Configure VPC Flow Logs in AWS and deliver them to an authorized S3 bucket.
For CloudWatch Logs, use the AWS export-to-S3 workflow. Export and retrieve
the objects using your existing AWS IAM permissions and the AWS CLI, for
example:

```bash
aws s3 cp 's3://YOUR-BUCKET/YOUR-KEY/vpcflow.log.gz'   /tmp/vpcflow.log.gz
python3 shared/bin/aws_vpc_flow_to_json.py /tmp/vpcflow.log.gz   > /tmp/vpcflow.ndjson
```

The tool reads plain `.log` and gzip `.gz` files without loading the entire
export into memory. Both direct VPC-to-S3 records and CloudWatch export
records prefixed by a millisecond UNIX timestamp are supported. Input is
never modified. Multiple paths and standard
input (`-`) are supported. Default behavior **fails on malformed records**
with filename and line number; use `--skip-invalid` only after deciding how
to handle omitted records.

For custom AWS field orders, either include the AWS field header at the top
of the export, or pass the comma- or space-separated order explicitly:

```bash
python3 shared/bin/aws_vpc_flow_to_json.py   --fields 'version account-id interface-id srcaddr dstaddr srcport dstport protocol packets bytes start end action log-status region'   /tmp/vpcflow-custom.log > /tmp/vpcflow-custom.ndjson
```

VPC Flow Log status events such as `NODATA` and `SKIPDATA` remain visible;
missing values represented by `-` are not fabricated as network addresses.
Account IDs remain strings to preserve leading zeros.

## 2. Configure Malcolm's TCP log receiver

Enable the existing Filebeat TCP input using
[`config/filebeat.env`](malcolm-config.md#MalcolmConfigEnvVars),
normally generated by `./scripts/configure`:

```text
FILEBEAT_TCP_LISTEN=true
FILEBEAT_TCP_LOG_FORMAT=json
FILEBEAT_TCP_PARSE_TARGET_FIELD=miscbeat
FILEBEAT_TCP_TAG=_malcolm_beats
```

Retain `BEATS_SSL=true` in `config/beats-common.env`. Restart the
filebeat service with Malcolm's normal deployment commands. On a Docker
Compose installation, port 5045 is bound to localhost by default. If
sending from a separate host, configure an explicitly trusted private
listener, a firewall allowlist, and valid TLS certificates. Avoid publishing
this ingestion endpoint on the public Internet.

## 3. Send records using verified TLS

The converter can connect to Malcolm's listener directly without an extra
forwarder. Use a trusted certificate authority and verify the **DNS name
in the receiver's certificate**:

```bash
python3 shared/bin/aws_vpc_flow_to_json.py   --send-host 127.0.0.1 --port 5045   --server-name 'YOUR-MALCOLM-CERTIFICATE-DNS-NAME'   --ca-cert filebeat/certs/ca.crt   /tmp/vpcflow.log.gz
```

When the receiver requires a TLS client certificate, also pass
`--client-cert /path/to/client.crt --client-key /path/to/client.key`.
Keep private keys protected and do not copy them to untrusted hosts.

The sender **always verifies the server certificate**, using the supplied
CA PEM file and expected DNS identity. It has no insecure/skip-verification
mode. If verification fails, fix the certificate, CA, name, or access
permissions rather than disabling TLS checks.

The tool also supports offline JSON export to stdout for inspection,
auditing, or use with an existing forwarding agent; it does not send
anything to Malcolm unless `--send-host` is specified.

## 4. Verify ingestion

For recognized fields, Malcolm's Logstash pipeline populates:

| AWS VPC Flow Log field | ECS field |
| --- | --- |
| `account-id` | `cloud.account.id` |
| `region` (if present) | `cloud.region` |
| `srcaddr`, `dstaddr` | `source.ip`, `destination.ip` |
| `srcport`, `dstport` | `source.port`, `destination.port` |
| `packets`, `bytes` | `network.packets`, `network.bytes` |
| `protocol` | `network.transport` |
| `action` | `event.action` |

The records have `event.module: aws_vpcflow` and
`event.dataset: aws.vpcflow`. The raw record remains in `event.original`,
while other exported fields remain under `miscbeat`.

Check that the expected records appear in OpenSearch Dashboards and that
the account, source/destination, count and action match the AWS export.
Malcolm's ingestion pipeline can deduplicate identical records according
to its existing fingerprint and index settings. Replay only the records
you intentionally want imported.

This is one supported cloud log type under [issue #468](https://github.com/cisagov/Malcolm/issues/468).
Other AWS products (ELB, CloudFront, Route 53, RDS), Azure, and continuous
cloud subscription polling require their own source-specific forwarding
and parsing configuration. They are not automatically supported by this
VPC Flow Log converter.
